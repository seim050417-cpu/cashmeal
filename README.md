## 0-1. 이번 업데이트 (검증 프로젝트 기준 XML 구조 반영)

별도로 실제 RDA API 호출에 성공한 검증 프로젝트(cashmeal-app-v3)의 응답 구조를 그대로 반영해서 `server.js`의 파싱 로직만 교체했습니다. UI(`public/index.html`)는 전혀 건드리지 않았습니다.

- API② 실제 구조가 "재료 목록이 바로 나열"되는 게 아니라 **메인 음식 1건 안에 `idnt_List`라는 재료 목록이 중첩**되어 있는 구조였습니다. 기존 코드는 이 중첩을 반영하지 못해서 재료 데이터를 제대로 못 꺼내고 있었어요 → 수정 완료.
- 오류/정상 여부를 `response.header.result_Code` / `result_Msg`로 정확히 읽도록 수정.
- 영양소 필드를 실제 확인된 이름(`na_Qy`=나트륨, `fibtg_Qy`=식이섬유, `clci_Qy`=칼슘, `phph_Qy`=인, `ptss_Qy`=칼륨 등)으로 전부 매핑해서 더 풍부한 실제 데이터를 내려줍니다.

## 0-2. 이전 업데이트에서 고친 것

- **API① 엔드포인트 오류 수정**: 기존에는 `MzenFoodCode1`까지만 호출해서 계속 400이 났어요. 실제로는 `MzenFoodCode1/getKoreanFoodList1`까지가 정확한 호출 주소였습니다.
- **영양소 필드명 수정**: 나트륨 필드를 `na_Qy`로 정확히 매핑했습니다.
- **저장 방식 수정**: 기존에는 실제 브라우저에 존재하지 않는 `window.storage`를 사용해서 새로고침하면 데이터가 저장되지 않고 있었어요. 이제 표준 `localStorage`를 사용합니다.
- **오류 처리 방식 변경**: API 호출이 실패하면 더 이상 데모 데이터로 조용히 대체하지 않고, "음식 데이터를 불러오지 못했습니다"처럼 명확히 알려드립니다. (검색 결과가 0건인 것과 API 오류는 구분해서 표시)

# 캐시밀 (cash meal) - RDA API 연동 백엔드

> **배포(외부에 공개된 주소로 올리기)하고 싶다면 `DEPLOY.md`를 보세요.** 이 문서는 로컬(내 컴퓨터)에서 실행하는 방법을 설명합니다.

이 프로젝트는 다음 구조로 동작합니다.

```
[브라우저 (HTML/CSS/JS)]
        ↓  fetch("/api/foods?name=...")
[Node.js + Express 서버 (server.js)]
        ↓  serviceKey를 붙여 실제 호출
[RDA 공공데이터 API]
```

프론트엔드는 RDA API를 절대 직접 호출하지 않고, 항상 우리 서버(`/api/foods`, `/api/foods/:code`)만 호출합니다.
RDA 서비스키는 `.env` 파일에만 있고, 프론트엔드 코드(public 폴더 안)에는 전혀 들어있지 않습니다.

---

## 1. 처음 한 번만 하는 준비

### 1) Node.js 설치
- https://nodejs.org 에서 **LTS 버전**을 다운로드해서 설치하세요.
- 설치 후 터미널(맥: 터미널 / 윈도우: PowerShell 또는 명령 프롬프트)에서 아래를 입력해 설치가 됐는지 확인하세요.
  ```
  node -v
  npm -v
  ```
  버전 숫자가 나오면 성공입니다.

### 2) 프로젝트 폴더 열기
- 압축을 푼 `cashmeal-app` 폴더로 터미널에서 이동합니다.
  ```
  cd 경로/cashmeal-app
  ```

### 3) 필요한 패키지 설치
```
npm install
```
- `express`(서버), `axios`(RDA API 호출), `xml2js`(XML→JSON 변환), `dotenv`(.env 읽기)가 설치됩니다.

### 4) API 키 입력 ⭐가장 중요⭐
- `cashmeal-app` 폴더 안의 **`.env`** 파일을 텍스트 에디터(메모장, VS Code 등)로 엽니다.
- 아래 줄을 찾아서
  ```
  RDA_SERVICE_KEY=여기에_사용자가_직접_입력
  ```
  `여기에_사용자가_직접_입력` 부분만 지우고, 공공데이터포털에서 발급받은 서비스키를 붙여넣습니다.
- 저장합니다. (이 파일은 `.gitignore`에 등록되어 있어서 깃허브 등에 절대 올라가지 않습니다.)

브라우저 주소창에 아래 주소를 입력하세요.
```
http://localhost:3000
```
평소 보던 캐시밀 앱 화면이 그대로 나오면 정상입니다. (UI/기능은 그대로 유지했습니다.)

---

## 4. 실제 RDA API가 연결됐는지 테스트하는 방법

서버를 켠 상태에서, 브라우저 주소창에 아래 주소들을 하나씩 입력해보세요.

1. **서버 상태 확인**
   ```
   http://localhost:3000/api/health
   ```
   `"keyConfigured": true` 이면 키가 잘 설정된 것입니다.

2. **음식 검색 테스트** (예: 김치찌개)
   ```
   http://localhost:3000/api/foods?name=김치찌개
   ```
   `"source": "rda_api"` 와 함께 실제 음식 목록(JSON)이 보이면 연동 성공입니다.

3. **음식 상세정보 테스트** (예: D065003)
   ```
   http://localhost:3000/api/foods/D065003
   ```
   재료 목록과 영양정보(JSON)가 보이면 성공입니다.

앱 화면에서는 음식 검색창에 검색어를 입력했을 때, 결과 옆에 "실시간 RDA 데이터" 배지가 붙으면 실제 연동이 된 것이고,
"데모 데이터" 배지가 붙으면 서버 호출이 실패해서 목업으로 대체된 상태입니다(화면이 깨지지 않도록 자동 대체됩니다).

---

## 5. 잘 안 될 때 (문제 해결)

- **`keyConfigured: false`** → `.env`에 키가 안 들어갔거나 저장이 안 된 것입니다. 다시 확인해주세요.
- **`RDA API 오류 응답` 메시지** → 서비스키가 틀렸거나, 아직 활용신청이 승인되지 않았을 수 있습니다. 공공데이터포털에서 해당 API의 활용신청 상태를 확인하세요.
- **인증 관련 오류가 계속될 때** → 공공데이터포털은 키를 "인코딩"과 "디코딩" 두 가지 형태로 제공합니다. 지금 넣은 키가 안 되면 다른 형태의 키로 바꿔서 다시 시도해보세요.
- **`/api/foods/:code` 응답에서 영양정보 필드가 비어있을 때** → RDA API②의 실제 응답 태그명이 저희가 예상한 이름(`energy_Qy`, `prot_Qy` 등)과 다를 수 있습니다. 위 3번 테스트 주소로 실제 JSON을 열어서 `raw` 항목 안의 실제 필드명을 확인한 뒤, `server.js`의 `nutrients` 매핑 부분만 그 이름에 맞게 고치면 됩니다.
- **포트 3000이 이미 사용 중일 때** → `.env`의 `PORT=3000`을 다른 숫자(예: 4000)로 바꾸고 다시 `npm start` 하세요.
